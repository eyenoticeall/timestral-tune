# Documentation Index

| File | What it is | Updated |
|---|---|---|
| [`SPEC.md`](SPEC.md) | Specification and overview guide: design, API, acceptance tests, roadmap, decisions, risks | When design or decisions change |
| [`../AGENTS.md`](../AGENTS.md) | Rules, commands, session workflow, commit conventions | When the way of working changes |
| [`STATUS.md`](STATUS.md) | Current state and next steps | Every session |
| [`DEVLOG.md`](DEVLOG.md) | Dated log of what was done and why | Every session (append) |
| [`VERIFICATION.md`](VERIFICATION.md) | Measured evidence behind the spec's `[V]` tags, with reproduction commands | When a measurement is added or re-run |
| [`UPSTREAM.md`](UPSTREAM.md) | Pinned upstream versions, vendoring and re-vendoring procedure | When pins change |
| [`DEVELOPMENT.md`](DEVELOPMENT.md) | Setup, commands, layout, testing strategy | When tooling changes |
| [`phases/`](phases/) | Working notes per roadmap phase | While that phase is active |

Each fact has one home (see `AGENTS.md` §2). The roadmap checklist lives only in the spec, §10; the
phase files hold notes and evidence, not a second checklist.
